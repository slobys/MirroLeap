# MirroLeap v5.3.5 · 投屏启动稳定性及过期 HQ 缓存修复

## v5.3.5 · 紧急回归修复

- **修复可选 scrcpy 5.0.1 HQ 接收器的内存布局错误**：主程序和 D3D11 模块对同一结构体使用不同编译宏，导致初始化时可能越界写入并触发投屏进程异常退出。现统一内存布局，并添加两种编译模式的结构体大小回归检查。
- **避免升级后复用旧核心**：仅认与本次发布 SHA-256 完全一致的可选 HQ 核心缓存；新组件使用 SHA-256 区分的目录。普通 USB/Wi-Fi 投屏不会自动下载高清组件。
- 保留 600ms 青色点击波纹、2.35× 固定倍率、D3D11 自适应 80/100/140ms 和慢读回保护，不新增默认开启的实验功能。
- 本版为 **Pre-release**，Windows 自动化构建的安装包仍需在用户真实安卓设备上验收 USB/Wi-Fi、横竖屏和连续视频；不能仅凭 CI 宣称已彻底消除断线或拖尾。

## v5.3.4 · 高清放大响应优化与 600ms 点击波纹

## v5.3.4 · 真机反馈后的延迟优化

- 点击特效扩散及淡出共 **600ms**（旧版 1800ms），仍为独立 Windows 透明穿透窗口。
- HQ D3D11VA 原始帧采样由固定 125ms 改成按真实 GPU 下载时间自适应调节，分别为 80/100/140ms；CPU 圆形镜头渲染间隔由 50–160ms 缩为 32–120ms，保留当前 2.35 倍画质。
- GPU 读回连续两次超过 45ms 时自动回退，正常 scrcpy 5.0.1 显示通路不受源帧限频影响。仍是实验性 CPU/GDI 全帧路径，并非零拷贝 GPU 高清，需要真机验证响应和 FPS。

## v5.3.3 · D3D11 原始帧实验基础

## v5.3.3 · 解决旧 scrcpy 4.0 核心切换问题

- 普通 MirroLeap 不变：5 MB 左右主 EXE、原名称与安装身份、签名一键更新、默认 2.35 倍悬浮放大仍不在设置中重复出现。
- 只有选择「原始帧高清（实验功能）」才按需下载独立的 `MirroLeap.HQ.Core_v3_x64.zip`。本版改为固定 Genymobile/scrcpy **5.0.1**、提交 `a60891aea193d92e7e5c3942700eca63f9d19a5f`，而不是旧版 4.0；支持 scrcpy 5.x 的 `--hwdec=d3d11va` 和“Video decoding”日志。
- 通过 FFmpeg `AVFrame` 的 GPU 纹理引用把解码帧传给可选后台工作线程，而不是在解码主线程做 GPU→CPU 传输。仅读取圆形放大镜需要的源帧，至多 8 次/秒 D3D11VA 全帧 GPU 读回，并保持原有 YUV420P/NV12 双槽 IPC。
- 每次 GPU 下载计时，连续两次超过 45ms 时禁用本次会话的原始帧旁路并由旧 Windows 实时放大镜回退。目标是防止 GPU 镜头拖慢正常视频。
- **技术边界：** D3D11VA 视频硬解≠D3D11 GPU 高清圆圈；目前依旧需要整帧 GPU→CPU 下载及 CPU/GDI 局部插值，尚未实现 GPU ROI 或跨进程纹理共享，不能保证抖音视频流畅或消除锯齿。Windows 编译/桌面测试不能代替真实 Android 视频验收。
- 旧缓存 `hq-runtime-v2` 不会被自动信任或覆盖，新核心存储在 SHA-256 区分的 `hq-runtime-scrcpy501-v3-<哈希前缀>` 目录；普通投屏不加载实验组件。

## v5.3.2 · 隐藏固定 2.35 倍设置

## v5.3.2 · 隐藏固定 2.35 倍设置

- 默认实时放大仍是 **2.35 倍**，直接从手机悬浮栏开启，不需要在「GPU 解码与性能」里另行勾选。移除重复的默认倍率设置、提示和相关 UI 测试。
- 设置页仅保留独立 **“原始帧高清（实验功能）”** 选项，默认关闭。普通实时放大始终使用已安装的 scrcpy 5.x 及原有解码参数；只有用户明确选择实验功能才会下载/切换单独的 scrcpy 4.0 核心。
- 历史设置中 hqLens=true、hqExperimentalCore=false 的普通用户也不会自动切换实验核心，降低误操作导致的视频卡顿风险；原 MirroLeap 安装标识、一键更新通道与轻量安装包不变。
- GPU 原始帧高清仍处于开发阶段，默认桌面放大不是原始帧无损高清。

### v5.3.1 · 恢复普通投屏流畅引擎，原始帧实验单独开启

## v5.3.1 · 性能优先模式（同一款 MirroLeap）

- 问题原因：过去勾选 HQ 就将正常投屏 scrcpy 5.0.1 切换到实验性 scrcpy 4.0，普通核心的 Windows D3D11VA 解码选项因此不能应用。即使 v5.3.0 缩减 YUV 帧复制，也不能解决引擎切换带来的全部卡顿。
- 从此“2.35× 实时放大（流畅优先）”默认继续使用原来的 scrcpy 5.x 引擎与对应解码参数。它放大的是桌面视频像素，并非原始解码帧高清，界面会明确告知这一限制。
- **仅手动再次开启**“实验性原始帧高清（切换 scrcpy 4.0，可能卡顿）”才会安装/调用 v2 HQ 运行库。这样保留真实源帧高清实验，但不会牺牲绝大多数用户的普通视频流畅度。
- 旧版仅有 hqLens=true 的用户配置自动归入流畅模式，避免更新后继续调用实验视频引擎；新开关仍需停止、重启投屏才会生效。
- 当前没有实现 D3D11 GPU 原始解码帧纹理高清镜头，不能以“默认流畅”模式冒充最终高清。后续需独立开发 GPU 镜头，同时使用持续播放视频做同条件帧率测试。
- 保持原来的 MirroLeap 安装标识、签名更新通道和约 5 MB 的 EXE 包体积；v2 HQ 核心仍是可选独立组件。

## 你可以直接从 MirroLeap v5.2.3 更新

- v5.2.3 原程序会检索仓库中的 `vX.Y.Z` 版本，并检查是否有完整的 NSIS 安装包、minisign 签名与 `latest.json`。本次使用正常的 `v5.3.5` 标签和 `MirroLeap_5.3.5_x64-setup.exe` 文件名。
- 已安装的 NSIS EXE：启动时检测新版，弹窗由用户确认后，下载并验证固定公钥签名再安装；不是静默升级。
- MSI、便携 ZIP：可以收到新版提示，但出于安装方式安全边界，需要自行下载安装对应的新版本，不能被 NSIS 自动覆盖。
- 注意仅存在于旧 “HQ Preview” 独立程序中的旧标识不自动合并或卸载；原来的 MirroLeap v5.2.3 更新链完全延续。
- Windows SmartScreen 或来源提示仍可能存在：项目的 minisign 更新签名不是微软认可的 Authenticode 发布证书，请不要关闭系统安全保护。

## v5.3.0 · HQ 按需传帧 / CPU 限频 / 实际解码状态

- 在实验性 scrcpy 4.0 的共享帧头升级协议至 v2，增加消费者按需启停位。打开 HQ 选项但没有真正使用实时放大圈时，客户端不再无条件克隆或复制完整 1080P/2K YUV 帧；仅在圆圈开启、鼠标位于前台手机视频内时才取帧。
- C 源帧复制频率上限 20 次/秒（新帧优先），CPU/GDI 镜头根据上次绘制耗时独立限频。**它们不会主动限制普通 scrcpy 视频的 60 FPS 上限**，也不能把静止桌面测得的 11 FPS 当成网络、解码必然卡顿的证据。
- HQ 若只有 FPS 日志、没有视频硬解/软解报告，界面明确显示“核心未报告解码方式（无法确认 GPU）”，不再无限等待；普通 scrcpy 5.0.1 的 D3D11VA 配置不等于本次运行的 HQ scrcpy 4.0 实验核心实际启用了硬解。
- 旧 v1 HQ 核心不认识按需开关。因此首次运行新版 HQ 时会 SHA-256 校验后**一次性下载独立 v2 HQ 核心**，储存到不同缓存目录；正常的 MirroLeap EXE 仍约 5 MB，旧版签名一键更新不变。
- 这是 CPU/内存带宽减负，不保证所有视频都到 60 FPS。真机 1080P/2K 持续视频测试仍需进行，真正的 D3D11 GPU 高清纹理渲染尚未交付。

## v5.2.9 · 修复 HQ 原始帧已到达但放大圆圈消失

- 修复 Windows HQ 分层圆形窗口“已接收 864×1920 等真实解码帧、悬浮栏显示 HQ，但手机画面看不到放大圆圈”的问题。原实现成功提交 BGRA 后只调用 `ShowWindow`，没有明确把 HQ HWND 放到与 scrcpy SDL 一样的最上层；真机边框和投屏视频重新置顶后可能盖住它。
- 新实现使用非激活的 `SetWindowPos(HWND_TOPMOST)` 显示 HQ 像素，并且每次视频跟随刷新都核对真实的 HWND 可见性、位置与当前手机投屏视频/边框/工具栏的 Z 顺序。即使手机停在静止画面、没有新帧，也会恢复被挡住的放大圆圈。
- 窗口层级或绘制调用失败时立刻恢复既有 Windows Magnification.dll 2.35× 实时放大镜；连续异常时禁用本次实验性 HQ 窗口，避免出现按钮已启用但什么都不显示的状态。
- Windows CI 新增模拟一个重新置顶的 SDL 手机视频窗口，并通过真实 DWM 合成桌面截图验证 HQ 圆形画面仍能覆盖其上；只靠 `UpdateLayeredWindow` 返回成功不算通过。
- 这是 Windows 自动化环境的窗口层级修复，仍需在用户 Android 设备中确认实际表现；D3D11 GPU 最终高清方案仍在后续研发。

## 小安装包，高清功能可选

- 主安装包 **没有**打入实验性 scrcpy 4.0、FFmpeg/SDL3 或 ADB；EXE 目标回归约 5 MB。仍旧保持 USB、Wi-Fi、手机边框、画笔、截屏与创作者功能。
- 平常投屏仍按原方式使用已经安装的 scrcpy 引擎，不在软件启动和普通投屏时下载可选 HQ 核心。
- 只有在设置中明确勾选“可选 2.35× 高清放大”时，软件才下载单独的 `MirroLeap.HQ.Core_v3_x64.zip`，比对编译时固定的 SHA256，再校验 ZIP 结构和 scrcpy 4.0 补丁标志后保存到个人应用数据目录。中断、文件损坏或校验失败不会替换正常 scrcpy。
- 可选 HQ 会使用同一个 Android 视频流中的原始解码帧，经双槽共享内存与 2.35 倍局部采样显示独立 Windows CPU/GDI 圆形镜头；无帧时保留原有桌面实时放大作为回退。
- 增强的点击光圈、较长的可见时间和真实桌面像素 CI 验证，以及自适应抗混叠和画质来源提示，也包含在此版 MirroLeap 内。

## 当前验收边界

Windows Actions 会执行 Rust/前端测试、实验 scrcpy 4.0 真正编译、WebView2 启动、桌面点击特效截图、签名一致性和安装包体积门槛。但在没有连接真实 Android 的 CI 中，仍无法宣称 **D3D11 GPU 高清镜头**已完成，也不能承诺 1080P/2K 抖音视频放大在实际设备上无锯齿、60fps 或更低延迟。当前 HQ 是可选 CPU/GDI 实验路径。
